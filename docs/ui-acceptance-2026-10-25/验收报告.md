## 必须处理的问题

### UI-01 · P1 · 首页当前导航与山石混在一起

**复现：** 1440×900，浅色主题，打开 V2 首屏，查看左侧「日历」。

当前导航文字位于左侧深色山石上，15px 赭色文字缺少稳定纸底，辨识明显弱于另两个导航。实际 CSS 色为 `rgb(119,61,39)`；固定减少动态帧，在字形及阴影变化范围取 136 个背景样本，文字色与背景的局部对比度约 **1.00–2.78:1**，低于操作文字 4.5:1 的目标。此采样用于证明画作冲突，不能替代整页 WCAG 认证。

`acceptance.css` 第 20 行的 `background:transparent` 覆盖了 `skeleton.css` 第 294 行为导航添加的纸色渐隐。建议恢复足够不透明的窄纸底，分别复核三个导航在明暗主题和不同构图中的可读性。

证据：[首页](01-hero.png)、[固定帧](18-nav-visible.png)、[去除文字后的背景](18-nav-background.png)、[对比度数据](contrast-evidence.json)。

### UI-02 · P2 · 手机多处通用按钮低于 44px 触区

**复现：** 390×844 或 320×740，进入日历，检查顶部工具与翻月按钮。

实测搜索、主题按钮为 **36×36px**，前后月为 **32×36px**，回到今天/随机穿越高度 **36px**，暂停动效高度 **40px**。V2 基线要求通用触区至少 44×44px；日期格是明确允许的窄屏特例，不能把该特例扩展到通用操作。320px 日期格实测约 **36.4×44px**，中心点击能正确选日，本项不把它计为错误。

建议扩展控件实际命中区域并复核相邻触区不重叠；不要求放大图标本身。关联规则：`skeleton.css` 第 168、264、268、289 行。

证据：[390px 日历](09-mobile-calendar.png)、[320px 日历](13-320-calendar.png)、[尺寸数据](supplement-results.json)。

### UI-03 · P2 · 320px 首屏没有形成“日期＋史事”的信息层

**复现：** 320×740，进入日历，选择 2026-07-11，保持进入日历后的默认位置。

标题右侧两个操作按钮换成上下两行，加上完整月历和分开的日签卡，首条「郑和首次下西洋」标题位于视口 **y=791–818px**；固定底部导航从 **y=683px** 开始，首条事件完全不在首屏。页面可继续滚动，未构成内容无法访问，但未达到场景 09 的首屏信息层目标。

建议优化窄屏标题操作区及月历/日签间距，或提供明确的紧凑默认布局；不要通过继续缩小字体与点击区域解决。关联规则：`skeleton.css` 第 262–274、288–292 行。

证据：[320px 默认日历位置](13-320-calendar.png)、[首条事件与底栏坐标](final-evidence.json)。390px 首屏可见事件标题，但正文仍需下滚，不应据此推广为所有手机尺寸通过。

### UI-04 · P2 · 选中日期仍是方框，缺少规定的朱砂圆印

**复现：** 进入日历，点击任一日期，分别查看桌面与手机。

当前选中格是淡红矩形和一圈方形描边，实际 `border-radius:0px`；`d-num` 背景为 `none`。这与参考图及 V2 第 6 节要求的“朱砂圆印＋on-zhu 日期字”不符。今天和选中态也需要继续分别表达。

建议在数字层制作圆形印记，保留日期格完整点击区域，避免把整格变成大红块。关联规则：`skeleton.css` 第 81、84、86 行。

证据：[桌面日期](02-calendar.png)、[手机日期](09-mobile-calendar.png)。

### UI-05 · P2 · 小屏正文与出处偏小，跨月日期叠加透明度后过淡

**复现：** 手机日历选择有史日，阅读摘要/出处，再查看月初月末的非本月格。

手机 `.ev-desc` 实测 **13px**、`.ev-src` **11px**；V2 字阶要求正文 16px、出处/标签 12px，11px 特例不用于史料出处。非本月格整体透明度 0.52，农历再乘 0.8，有效透明度 **0.416**。在 320px 实际纸面采样中，其农历文字合成后对比度约 **1.88:1**，可点击日期却呈现近似不可用的灰字。

建议恢复正文与出处字阶，用字色、边界或背景区分跨月格，避免给整格套透明度。关联规则：`skeleton.css` 第 84、269、274 行，`app.css` 第 537 行。此问题针对摘要/辅助日期，未发现阅读弹层主要正文无法阅读。

证据：[手机日历](09-mobile-calendar.png)、[暗色日历](17-dark-calendar.png)、[颜色及透明度数据](contrast-evidence.json)、[实际字号](supplement-results.json)。

### QA-01 · P2 · 素材清单仍引用已移除文件，交付校验失败

**复现：** 项目根目录执行 `node v2/qa/check-asset-integration.cjs`。

命令报错：`素材清单文件缺失：assets/brand/yiye-qianqiu-seal.png`。完整检查发现 `manifest.json` 共 179 条栅格登记，**90 条路径在当前仓库不存在**，主要为已经归档/移除的 PNG。实际浏览页面中的 WebP、字体和图标未出现 HTTP 4xx/5xx，因此应区分“验收清单过期”和“用户页面图片加载失败”。

建议按发布时实际消费的 WebP 重建清单，将归档母版另列说明，使 README 指定的校验命令能够通过；不要仅删除文件存在性断言。关联位置：`v2/assets/manifest.json` 第 5 行及后续 PNG 条目、`check-asset-integration.cjs` 第 34–37 行。

证据：[全部缺失登记](manifest-missing.json)、[实际请求记录](supplement-results.json)。README 还引用了仓库不存在的 `docs/v2-ui-review/修复记录.md`，交付证据入口也应同步更新。
