# v2 工作计划分析

> 针对「把《一页千秋》按交互式数字艺术展重做」这套方案的评估与排期。结论先说：**方案的判断是对的，但优先级排错了两处，且漏了一个必须现在决定的问题——发布哪一版。**

---

## 一、我完全同意的三条

1. **不做传统日历网站，做交互式数字艺术展。** 34% 的内容覆盖率注定它无法当工具用；它的价值确实在「从一天走进一段历史」的那一下。
2. **不增加动画数量，只完善衔接。** v1 已经具备雾、舟、墨晕、朝代换色、纸纹五套动效。再加只会更吵。
3. **优先打磨「点击史事 → 墨晕入画 → 阅读 → 返回」这一条链路。** 这条链路决定第一次惊艳程度，也是唯一值得用 750ms 的地方。

---

## 二、两处优先级要改

### 1.「统一三视图运动语义」不是 P1，是 P0

原方案把它放在 P1（「让整体体验形成一个世界」）。但三视图的运动方向一旦不统一，用户会持续感到「这不是一个东西」——这是**结构性**的判断，不是打磨。它必须在画第一条线之前定，事后再改等于重排所有页面。

v2 已按此执行：日历纵向、长卷横向、四时环形，换尺度只做 500ms 淡入，不与任何方向性动作复用。

### 2.「小字体、低对比度」要给出可验收的门槛，否则会修不干净

原方案写「解决小字体、低对比度问题」是对的，但没有量化标准，容易改一半。v2 把它落成三条硬线：

| 项 | 门槛 | v1 实际 |
|---|---|---|
| 正文对比度 | ≥ 4.5:1 | `--faint` 2.33:1，19 处 |
| 中文字号 | ≥ 11px | 9.5 / 10px 承载真实信息 |
| 朝代色作文字 | ≥ 4.5:1 | 唐 `#C08123` 仅 2.86:1 |

配套做法：颜色拆成「装饰值 / 可读值」两份（`--era` / `--era-ink`），字号不足时用字距与颜色换层次，不缩字号。

---

## 三、一个原方案没提、但必须现在定的问题

**11 月 1 日要提交作品，而 v2 是一次整体重做。**

如果让 v2 去顶替 v1 参赛，风险极高：全新交互链路、全新配色阶梯、全新响应式，任何一处没跑通都会直接扣「完成度 40 分」。而 v1 虽然有小字与对比度问题，但功能是完整的、跑通过的。

我的建议是**双轨**：

| 轨道 | 分支 | 用途 | 时间 |
|---|---|---|---|
| 发布轨 | `v1`（现状，只修 P0 硬伤） | 11-01 提交、社媒、表单 | 本周内完成 |
| 迭代轨 | `v2`（新目录，独立） | 11-01 后的版本，或明年参赛 | 不设死线 |

v1 那侧只需要做三件事：辅助文字换 `--muted`、字号下限抬到 11px、补古代内容。**不要动 v1 的交互**，任何改动都可能引入回归。

## 五、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| v2 交互链路在低端机上卡顿 | 入画 750ms 会掉帧 | 墨晕用 `clip-path`（合成层），山水只用 `opacity` + `scale`；已避开 filter 与 blur 大面积动画 |
| 双轨维护成本 | 改一处要改两边 | v2 复用 v1 的数据文件与图片，只重写视图层；数据只维护一份 |
| 素材风格不统一被评委看出来 | 直接影响「视觉」评分 | 要么统一重出，要么在长卷里改用同一套山水语言 |
| 提交时间被 v2 拖住 | 作品不上线等于零分 | v2 不影响 v1 发布，v1 这周必须投出去 |

---

## 六、一句话结论

原方案的**方向对、语言对、节奏也对**；需要修正的是「统一运动语义」应提前到 P0，以及必须明确 v2 不与发布轨抢时间。**先把 v1 投出去，再让 v2 长成一个完整的世界。**
